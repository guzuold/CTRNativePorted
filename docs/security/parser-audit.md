# Network parser review

- json.cpp / Parser::value now accepts at most 64 nested containers and throws std::invalid_argument before descending further. The same entry point covers auth3, peer/party envelopes and payloads, friend_verifier identity replies, matchmaking documents and store/session JSON. A missing object key at end of input now also fails before indexing the string.
- protocol.cpp / Reader::value reads BLOB and STRUCT lengths as UINT32 marker plus exactly four little-endian bytes, checks available bytes, then consumes the payload. It never calls value recursively. Protobuf fields and varints are iterative with existing byte/overflow checks.
- upnp.cpp / xml_value and service enumeration use bounded string searches and loops, not a recursive XML tree parser. Chunk decoding is iterative. No recursion limit was added to these already nonrecursive routines.
- friend_verifier.cpp uses the shared parse_json and inherits its limit. Friend/party verification performs a fixed outer-envelope and inner-payload parse, not recursive verification. Session multipart parsing and the DHT parse_message routine also scan iteratively. The DHT message saying splitting (recursive) is inside a loop, not a recursive parser call. This review is scoped to recursion; it does not assert that these parsers have no other security defects.
- dump_json and Json destruction remain recursive. Network-created trees are bounded at entry, including partially constructed trees during exception unwinding. The 1 MiB stack regression exercises parse, dump and destruction of both a 64-level array and a 64-level object before the malicious input; normal round trips must succeed. Application-created arbitrarily deep Json trees are outside this input guarantee.

Tests: server_test --security-json sends 65536 opening brackets to a 1 MiB stack thread; --security-blob sends 60000 BLOB markers and also rejects 60000 STRUCT markers. --security-http posts the deep JSON to the actual local HTTP /ctr/v1/peer endpoint and then confirms the service still answers.
